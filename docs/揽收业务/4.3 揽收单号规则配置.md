揽收单号规则配置用于识别管理端系统中暂未录入的尾程派送商面单单号，并根据预设规则判断扫描到的单号是否有效。

当系统识别出有效面单单号后，会将最终识别结果及扫描时间实时回传至管理端数据库进行存储。扫描记录仅作为新增数据保存，不修改管理端已有订单信息，也不会触发订单状态变化；即使扫描到的面单单号与系统现有订单匹配，也不会影响该订单当前状态。

页面主要由以下三个区域组成：

-   **全局配置**：设置允许扫描的面单最大长度，以及是否优先查询管理端现有订单。
-   **匹配规则列表**：维护不同服务商对应的单号识别规则、优先级及匹配方式。
-   **面单号测试**：输入测试单号，验证当前规则是否能够正确识别。

功能路径：配置中心 → 预约揽收单号规则

### 揽收单号识别逻辑解释

揽收面单识别过程可以概括为：

> 扫描面单 → 校验单号长度 → 查询现有订单（如开启） →
> 按优先级执行匹配规则 → 必要时进行子串提取 → 得到有效面单号 →
> 保存扫描记录

识别成功后，仅新增保存：

-   最终识别出的有效面单单号；
-   扫描时间。

扫描结果不会修改管理端已有订单数据，也不会触发订单状态流转。

### 全局配置
- 单号最大长度：用于限制可进入识别流程的面单单号长度。当前配置为：**32 位**，当扫描到的面单单号长度超过该值时，系统直接判定为无效单号并报错，不再继续执行匹配规则。修改最大长度后，点击右上角 **【保存】** 使配置生效。
- 开启【查询订单列表】后，系统在执行面单规则匹配前，会先查询管理端订单列表中是否已经存在该单号。整体处理逻辑为：
> 扫描单号 → 查询现有订单 → 已存在则无需继续匹配 →
> 不存在再进入规则匹配

### 匹配规则列表
匹配规则列表用于维护不同尾程派送商的面单号识别方式。

列表主要包含以下字段：
- 状态: 控制当前规则是否启用。关闭后，该规则不参与匹配。
- 服务商: 当前规则对应的尾程派送商。
- 优先级: 多条规则同时存在时的匹配顺序，数值越小优先级越高。
- 类型: 当前规则的处理方式，例如正则匹配、子串提取。
- 匹配表达式: 实际用于识别或提取面单单号的规则。
- 备注: 当前规则的补充说明。
- 更新时间: 最近一次修改规则的时间。
- 更新人: 最近一次修改规则的操作人。
- 操作: 点击【编辑】修改现有规则。

页面右上角的 **【+ 新增规则】** 可用于新增服务商匹配规则。

### 面单号测试

页面底部提供【面单号测试】功能，用于验证当前规则配置是否能够正确识别指定面单号。

操作步骤：

1.  在输入框中填写需要测试的面单单号。
2.  点击 **【查询】**。
3.  系统根据当前全局配置及已启用规则执行识别。
4.  查看返回的匹配结果。

新增或修改匹配规则后，可通过该功能对典型单号进行测试，确认规则是否符合预期。

### 常见问题
1. 为什么预约揽收的取货方式为“扫码取货”，但没有包裹单号，或取件数量与实际扫描数量不一致？
	
	可能是部分面单单号尚未配置对应的**单号匹配规则**，导致司机扫码时系统无法正确识别该单号，因此未生成对应的扫描记录，最终出现包裹单号缺失或取件数量与扫描数量不一致的情况。
	
	遇到此类问题时，可先检查对应服务商的单号规则是否已维护至【揽收单号规则配置】中；如规则缺失，请联系相关负责人新增或维护匹配规则。
